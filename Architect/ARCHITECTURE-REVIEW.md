Data flows:

- `read_buddy_config` Rust command → reads `~/.claude/` files → returns to JS
- `get_api_key` Rust command → OS keychain → returns to JS → Anthropic SDK streams directly from JS
- `get_git_activity` Rust command → `git log` subprocess → returns XP delta to JS
- Zustand store → all React components subscribe, no prop drilling past room level
- State mutations → debounced `write_state` Tauri command → `~/.buddy/state.json`

## 2. Tauri Backend Design

### What goes in Rust vs JS

**Rust (Tauri commands):**
- File system access to `~/.claude/` and `~/.buddy/` (path sandboxing, no CORS)
- OS keychain read/write (tauri-plugin-keychain, not available in WebView)
- Git subprocess execution (shell escaping, path resolution)
- Native file dialog for repo picker
- State file read/write with atomic writes (write to temp, rename)

**JS (frontend):**
- All Claude API calls (Anthropic SDK works fine in WebView, streams via SSE)
- Rive animation control
- MediaRecorder + Web Audio API
- All UI state, room routing, timers, XP calculation logic
- Message history (in-memory during session, persisted via Rust command)

## 3. State Management Design

Split the single `appStore.ts` into three focused stores. The current store tries to be everything and will become unmanageable as XP, chat history, stats, and kit cooldowns are added.

## 4. Buddy Reader Strategy

### Files to check in order

The waterfall from CEO-REVIEW.md is right. Here is the exact implementation:

```
Priority 1: ~/.claude/settings.json
  → Check for top-level "buddy" key or "character" key
  → Structure unknown until inspected; parse defensively

Priority 2: ~/.claude/buddy.json
  → Custom file written by /buddy command (existence unconfirmed)
  → Expected shape: { name, species, personality?, colors? }

Priority 3: ~/.claude/CLAUDE.md
  → Plain text; look for patterns like:
    - "my buddy is [name] the [species]"
    - "# Companion\n...[name]...[species]..."
    - The system-reminder block format used in this conversation

Priority 4: ~/.claude/projects/-Users-matedort/memory/MEMORY.md
  → Contains "project_buddy_app.md | Buddy App: ... Biscuit the dragon..."
  → Parse: extract species from "Biscuit the [species]" pattern

Priority 5: Claude API call (Haiku model)
  → Prompt: "I am a Claude Code user. What is my buddy character's name
    and species? Answer only with JSON: {name, species}"
  → Uses the stored API key, ~100 tokens, fast

Priority 6: Manual setup screen
  → Show form: "What's your buddy's name?" + species picker
```

### Rust implementation

```rust
// src-tauri/src/commands/buddy_config.rs

use std::path::PathBuf;
use serde_json::Value;

pub async fn read_buddy_config() -> Result<Option<BuddyConfig>, String> {
    let home = dirs::home_dir().ok_or("no home dir")?;
    let claude_dir = home.join(".claude");

    // Priority 1: settings.json
    if let Some(cfg) = try_settings_json(&claude_dir.join("settings.json")).await? {
        return Ok(Some(cfg));
    }

    // Priority 2: buddy.json
    if let Some(cfg) = try_buddy_json(&claude_dir.join("buddy.json")).await? {
        return Ok(Some(cfg));
    }

    // Priority 3: CLAUDE.md
    if let Some(cfg) = try_claude_md(&claude_dir.join("CLAUDE.md")).await? {
        return Ok(Some(cfg));
    }

    // Priority 4: MEMORY.md (project-scoped)
    let memory_path = claude_dir
        .join("projects")
        .join("-Users-matedort")
        .join("memory")
        .join("MEMORY.md");
    if let Some(cfg) = try_memory_md(&memory_path).await? {
        return Ok(Some(cfg));
    }

    Ok(None)  // JS side handles API fallback + manual setup
}

async fn try_settings_json(path: &PathBuf) -> Result<Option<BuddyConfig>, String> {
    let text = match tokio::fs::read_to_string(path).await {
        Ok(t) => t,
        Err(_) => return Ok(None),
    };
    let v: Value = serde_json::from_str(&text).map_err(|e| e.to_string())?;
    // Check known keys
    for key in &["buddy", "character", "companion"] {
        if let Some(b) = v.get(key) {
            if let (Some(name), Some(species)) = (
                b.get("name").and_then(Value::as_str),
                b.get("species").and_then(Value::as_str),
            ) {
                return Ok(Some(BuddyConfig {
                    name: name.to_string(),
                    species: species.to_string(),
                    personality: b.get("personality")
                        .and_then(Value::as_str)
                        .map(str::to_string),
                    colors: None,
                }));
            }
        }
    }
    Ok(None)
}

async fn try_claude_md(path: &PathBuf) -> Result<Option<BuddyConfig>, String> {
    let text = match tokio::fs::read_to_string(path).await {
        Ok(t) => t,
        Err(_) => return Ok(None),
    };
    // Pattern: "# Companion\nA small [species] named [name]"
    // Also checks system-reminder format used by Claude Code
    let re_companion = regex::Regex::new(
        r"(?i)A\s+(?:small\s+)?(\w+)\s+named\s+(\w+)"
    ).map_err(|e| e.to_string())?;
    if let Some(caps) = re_companion.captures(&text) {
        return Ok(Some(BuddyConfig {
            name: caps[2].to_string(),
            species: caps[1].to_lowercase(),
            personality: None,
            colors: None,
        }));
    }
    Ok(None)
}
```

Add `dirs = "5"` and `regex = "1"` and `tokio = { version = "1", features = ["full"] }` to Cargo.toml.

## 5. Claude API Integration

### Architecture decision: stream in JS, not Rust

The Anthropic SDK (`@anthropic-ai/sdk`) runs fine in the Tauri WebView. Making Claude API calls from Rust adds complexity for no gain. Keep all Claude calls in JS.

The API key is retrieved from keychain via Tauri command on startup and held in memory by the Anthropic SDK client instance. Never store it in Zustand (avoids accidental serialization to state.json).

```typescript
// src/lib/claudeClient.ts

import Anthropic from '@anthropic-ai/sdk'

let _client: Anthropic | null = null

export function initClaudeClient(apiKey: string): void {
  _client = new Anthropic({ apiKey, dangerouslyAllowBrowser: true })
}

export function getClaudeClient(): Anthropic {
  if (!_client) throw new Error('Claude client not initialized')
  return _client
}
```

### Streaming pattern

```typescript
// src/lib/streamBuddyResponse.ts

import { getClaudeClient } from './claudeClient'
import { useChatStore } from '../stores/chatStore'

export async function streamBuddyResponse(
  userMessage: string,
  buddyConfig: BuddyConfig,
  buddyState: BuddyPersisted,
): Promise<void> {
  const store = useChatStore.getState()
  const msgId = store.startBuddyStream()
  const client = getClaudeClient()

  const systemPrompt = buildSystemPrompt(buddyConfig, buddyState)

  // Last 20 messages as context (avoid context bloat)
  const history = store.messages
    .filter(m => !m.isStreaming)
    .slice(-20)
    .map(m => ({
      role: m.role === 'user' ? 'user' as const : 'assistant' as const,
      content: m.text,
    }))

  try {
    const stream = client.messages.stream({
      model: 'claude-haiku-4-5',   // Haiku: fast + cheap for chat; Sonnet for complex asks
      max_tokens: 512,
      system: systemPrompt,
      messages: [
        ...history,
        { role: 'user', content: userMessage },
      ],
    })

    for await (const chunk of stream) {
      if (chunk.type === 'content_block_delta' && chunk.delta.type === 'text_delta') {
        store.appendToStream(msgId, chunk.delta.text)
      }
    }
    store.finalizeStream(msgId)
  } catch (err) {
    store.finalizeStream(msgId)
    // Surface offline/error state
    if (isNetworkError(err) || isAuthError(err)) {
      store.appendToStream(msgId, offlineMessage(buddyConfig, buddyState))
      store.finalizeStream(msgId)
    }
  }
}
```

### System prompt design

```typescript
// src/lib/systemPrompt.ts

export function buildSystemPrompt(
  config: BuddyConfig,
  state: BuddyPersisted,
): string {
  const stageDesc = {
    baby: 'young and playful, a bit clumsy with words',
    teen: 'getting confident, slightly sarcastic, curious',
    adult: 'wise, direct, occasionally dry humor',
  }[state.stage]

  const hungerNote = state.stats.hunger < 20
    ? "You're very hungry and feeling sluggish. Your responses are shorter and you mention food."
    : ''

  return `You are ${config.name}, a ${config.species} companion for a software developer.
You are ${stageDesc}.
Personality: ${config.personality || 'playful and helpful'}.
XP: ${state.xp} (stage: ${state.stage}).

You live in the developer's desktop. You watch them code and care about their work.
Keep responses short — 1-3 sentences unless asked something complex.
You can be curious about what they're building. Occasional dry humor is good.
Never break character. Never mention you are an AI or Claude.
${hungerNote}
Current time context: the developer is actively working.`
}
```

### Model routing

- Standard chat: `claude-haiku-4-5` (fast, cheap, good enough for buddy personality)
- Complex asks (code review, architecture questions): detect keywords (`"review"`, `"what do you think about"`, `"help me design"`) and switch to `claude-sonnet-4-6`
- Buddy config API fallback: `claude-haiku-4-5` with 100-token max

### Context management

Keep last 20 messages in context. At 20 messages, trim the oldest 5. Never let the full history go to the API — the chat history in `chatStore` is the source of truth; the API call is always a fresh window.

For P2, persist the last 50 messages to `~/.buddy/state.json` under `chatHistory[]`.

### Save triggers

- On feed: immediate write (XP change + lastFeedingByFood update)
- On stat decay: debounced 5s write
- On XP change from git: immediate write
- On app quit: immediate write via `tauri-plugin-process` window close event
- On app open: compute stat decay from `lastStatDecayTs` to now, write result

Never save on every message. Chat history saves are batched: write every 10 new messages or on app quit.

### Atomic writes (Rust)

```rust
// src-tauri/src/commands/state.rs

pub async fn write_state(state: AppState) -> Result<(), String> {
    let path = state_file_path()?;
    let tmp = path.with_extension("tmp");
    let json = serde_json::to_string_pretty(&state)
        .map_err(|e| e.to_string())?;
    tokio::fs::write(&tmp, json).await
        .map_err(|e| e.to_string())?;
    tokio::fs::rename(&tmp, &path).await
        .map_err(|e| e.to_string())?;
    Ok(())
}

fn state_file_path() -> Result<std::path::PathBuf, String> {
    let home = dirs::home_dir().ok_or("no home dir")?;
    let dir = home.join(".buddy");
    std::fs::create_dir_all(&dir).map_err(|e| e.to_string())?;
    Ok(dir.join("state.json"))
}
```

### Migration strategy

Check `version` field on read. If missing or `< current`, run migration:

```rust
fn migrate(mut state: PersistedState) -> PersistedState {
    if state.version < 1 {
        // v0 → v1: add feedingStreak, lastFeedingDay
        state.buddy.feeding_streak = 0;
        state.buddy.last_feeding_day = None;
        state.version = 1;
    }
    // future: if state.version < 2 { ... }
    state
}
```

Always migrate on read, write back immediately if version changed.

## 7. Git Activity Reader

### Repo detection

The active repo path is stored in `state.json` under `buddy.activeRepoPath`. Set by the user via a repo picker dialog on first launch (or when null). The `pick_repo` Tauri command opens a native folder dialog filtered to directories.

Fallback for first launch before the user picks: scan for the most recently committed git repo under `~/` with a depth limit.

```rust
// src-tauri/src/commands/git.rs

use std::process::Command;

#[tauri::command]
pub async fn get_git_activity(repo_path: String) -> Result<GitActivity, String> {
    // Validate path exists and is a git repo
    let check = Command::new("git")
        .args(["-C", &repo_path, "rev-parse", "--git-dir"])
        .output()
        .map_err(|e| e.to_string())?;

    if !check.status.success() {
        return Err(format!("{} is not a git repository", repo_path));
    }

    // Commits in last 30 days by current user
    let since = "30.days.ago";
    let log = Command::new("git")
        .args([
            "-C", &repo_path,
            "log",
            "--oneline",
            "--no-merges",
            &format!("--since={}", since),
            "--format=%H",
        ])
        .output()
        .map_err(|e| e.to_string())?;

    let commits_last_30 = log.stdout
        .split(|&b| b == b'\n')
        .filter(|l| !l.is_empty())
        .count() as u32;

    // Timestamp of most recent commit
    let last_ts = Command::new("git")
        .args(["-C", &repo_path, "log", "-1", "--format=%ct"])
        .output()
        .map_err(|e| e.to_string())?;

    let last_commit_ts = std::str::from_utf8(&last_ts.stdout)
        .ok()
        .and_then(|s| s.trim().parse::<i64>().ok());

    Ok(GitActivity { commits_last_30, last_commit_ts })
}
```

```typescript
// src/components/BuddyCharacter/BuddyCharacter.tsx

import { useRive, useStateMachineInput } from '@rive-app/react-canvas'

interface Props {
  species: string
  stage: GrowthStage
  stats: BuddyStats
  expression?: 'idle' | 'happy' | 'hungry' | 'excited' | 'sleeping'
  fallback?: React.ReactNode   // shown while loading or if load fails

export function BuddyCharacter({ species, stage, stats, expression = 'idle', fallback }: Props) {
  const riveFile = `/rive/buddy-${species}-${stage}.riv`

  const { rive, RiveComponent, isLoading } = useRive({
    src: riveFile,
    stateMachines: 'BuddyStateMachine',
    autoplay: true,
    onLoadError: () => setHasError(true),
  })

  const [hasError, setHasError] = useState(false)
  const happinessInput = useStateMachineInput(rive, 'BuddyStateMachine', 'happiness')
  const hungerInput = useStateMachineInput(rive, 'BuddyStateMachine', 'hunger')
  const expressionInput = useStateMachineInput(rive, 'BuddyStateMachine', 'expression')

  // Sync stats to state machine inputs
  useEffect(() => {
    if (!rive) return
    if (happinessInput) happinessInput.value = stats.happiness
    if (hungerInput) hungerInput.value = stats.hunger
    if (expressionInput) expressionInput.value = expressionIndex(expression)
  }, [rive, stats, expression, happinessInput, hungerInput, expressionInput])

  // Show fallback during load and on error
  if (isLoading || hasError) {
    return <>{fallback ?? <BuddyPlaceholder species={species} />}</>
  }

  return <RiveComponent style={{ width: 120, height: 120 }} />

  return { idle: 0, happy: 1, hungry: 2, excited: 3, sleeping: 4 }[expr] ?? 0
}
```

```typescript
// src/lib/shareCode.ts

import { createHash } from 'crypto'  // available in Tauri WebView via Vite polyfill

export interface BuddyCard {
  version: 1
  name: string
  species: string
  stage: 'baby' | 'teen' | 'adult'
  stats: ArenaStats
  cosmetics: { colors: string[]; accessories: string[] }
  checksum: string
}

export function exportBuddyCard(
  config: BuddyConfig,
  state: BuddyPersisted,
): string {
  const stats = calcArenaStats(state)
  const card: BuddyCard = {
    version: 1,
    name: config.name,
    species: config.species,
    stage: state.stage,
    stats,
    cosmetics: { colors: config.colors, accessories: [] },
    checksum: checksumCard(config.name, config.species, state.stage, stats),
  }
  return btoa(JSON.stringify(card))
}

function checksumCard(
  name: string,
  species: string,
  stage: string,
  stats: ArenaStats,
): string {
  const payload = `${name}${species}${stage}${stats.hp}${stats.attack}${stats.defense}${stats.speed}`
  return createHash('sha256').update(payload).digest('hex').slice(0, 16)
}

export function importBuddyCard(encoded: string): BuddyCard | null {
  try {
    const card = JSON.parse(atob(encoded)) as BuddyCard
    const expected = checksumCard(card.name, card.species, card.stage, card.stats)
    if (card.checksum !== expected) return null  // tampered
    return card
  } catch {
    return null
  }
}
```

Note: `crypto` from Node is not available in the browser. Use the Web Crypto API instead: `crypto.subtle.digest('SHA-256', ...)`. Or use a tiny npm package like `hash.js`.

### Local battle engine

```typescript
// src/lib/battleEngine.ts

export type BattleAction = 'attack' | 'defend' | 'special'

export interface BattleTurn {
  actorName: string
  action: BattleAction
  damage: number
  targetHpAfter: number
  message: string
}

export function resolveTurn(
  attacker: { name: string; stats: ArenaStats },
  defender: { name: string; stats: ArenaStats; currentHp: number },
  action: BattleAction,
  attackerStage: GrowthStage,
): BattleTurn {
  const variance = 0.8 + Math.random() * 0.4   // 0.8–1.2
  let damage = 0

  if (action === 'attack') {
    damage = Math.floor(
      attacker.stats.attack * variance - defender.stats.defense * 0.5
    )
    damage = Math.max(1, damage)
  } else if (action === 'defend') {
    damage = 0  // skip turn, add defense bonus next turn
  } else if (action === 'special' && attackerStage !== 'baby') {
    damage = Math.floor(attacker.stats.attack * 1.5 * variance)
  }

  const targetHpAfter = Math.max(0, defender.currentHp - damage)
  return {
    actorName: attacker.name,
    action,
    damage,
    targetHpAfter,
    message: turnMessage(attacker.name, defender.name, action, damage, attackerStage),
  }
}

// Turn order: higher Speed goes first. Tie: attacker wins.
export function decideTurnOrder(
  a: ArenaStats,
  b: ArenaStats,
): 'a' | 'b' {
  return a.speed >= b.speed ? 'a' : 'b'
}
```

## 10. Security

### API key storage

Never store the Anthropic API key in `state.json` or anywhere on disk unencrypted. Use OS keychain exclusively.

```rust
// src-tauri/src/commands/keychain.rs

use keyring::Entry;

const SERVICE: &str = "buddy-app";
const USERNAME: &str = "anthropic-api-key";

#[tauri::command]
pub fn store_api_key(key: String) -> Result<(), String> {
    let entry = Entry::new(SERVICE, USERNAME).map_err(|e| e.to_string())?;
    entry.set_password(&key).map_err(|e| e.to_string())
}

#[tauri::command]
pub fn get_api_key() -> Result<Option<String>, String> {
    let entry = Entry::new(SERVICE, USERNAME).map_err(|e| e.to_string())?;
    match entry.get_password() {
        Ok(key) => Ok(Some(key)),
        Err(keyring::Error::NoEntry) => Ok(None),
        Err(e) => Err(e.to_string()),
    }
}

#[tauri::command]
pub fn delete_api_key() -> Result<(), String> {
    let entry = Entry::new(SERVICE, USERNAME).map_err(|e| e.to_string())?;
    entry.delete_credential().map_err(|e| e.to_string())
}
```

### CSP

Current `tauri.conf.json` has `"csp": null`. That is wide open. Set it:

```json
"security": {
  "csp": "default-src 'self'; script-src 'self'; connect-src https://api.anthropic.com https://api.openai.com; img-src 'self' blob: data:; style-src 'self' 'unsafe-inline'; media-src blob:; font-src 'self' data:"
}
```

`connect-src` covers the Anthropic SDK streaming. `media-src blob:` covers voice playback. `style-src 'unsafe-inline'` is needed for the inline style objects used throughout the React components — acceptable for a local desktop app with no user-provided HTML.

### Permissions (tauri.conf.json)

```json
"capabilities": [
  {
    "identifier": "main-window",
    "windows": ["main"],
    "permissions": [
      "core:default",
      "fs:allow-read-files",
      "fs:allow-write-files",
      "fs:allow-mkdir",
      "shell:allow-execute",
      "dialog:allow-open"
    ]
  }
]
```

File access scope: `~/.buddy/**` (read + write) and `~/.claude/**` (read only). Shell scope: `git` binary only.

### Data handled

- API key: OS keychain only, never logged, never serialized
- Chat messages: local `~/.buddy/state.json` only, never sent anywhere except to Anthropic API as conversation context
- Git history: only commit counts and timestamps, not commit messages or diffs
- Buddy config: read-only from `~/.claude/`, never written back

## Open Issues to Resolve Before Starting

1. **`~/.claude/` buddy format is unknown.** (Task 1 above.) Everything in Section 4 is based on inference. The actual key names in `settings.json` may differ. Do Task 1 first.

2. **`tauri-plugin-keychain` does not exist.** Use the `keyring` crate directly. Confirmed approach above. No blocker.

3. **`dangerouslyAllowBrowser: true` in Anthropic SDK.** This is required for browser environments and is correct for Tauri's WebView. The API key is secure because it comes from the OS keychain via Tauri IPC, not from a `.env` file baked into the bundle.

4. **Web Crypto API for SHA-256.** `createHash` from Node's `crypto` module is not available in the WebView. Use `crypto.subtle.digest('SHA-256', new TextEncoder().encode(payload))` and convert the ArrayBuffer to hex manually. Or use the `hash.js` npm package.

5. **`macOSPrivateApi: true` is already set.** Good. This is required for the transparent window to work correctly on macOS. Ensure the signing entitlements include the JIT exception or the app will crash at launch.

## Verdict

The foundation is sound. The UI shell, voice input, streaming cursor, and nav are all well-built. The three things that need to happen before any of it is real:

**Rust backend does not exist yet.** The `lib.rs` has only a `greet` command. All persistence, buddy config reading, keychain, and git activity live here. This is the biggest gap.
